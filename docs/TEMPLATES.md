# TEMPLATES — general TikTok slideshow structures that fit AI Onboard

Distilled from current builder guides (Sep 2026) + aionboard SALES_PLAYBOOK.
Rules that hold across sources: Photo Mode (swipeable, not Template auto-play),
1080×1920, 5–8 slides, one idea per slide, 10–15 words max, proof before CTA,
one CTA, trending audio picked in-app, manual post.

## House rules (all templates)
- Slide 1 names the buyer + problem, never the product. Product lives on last slide.
- Each slide earns the next swipe — never answer slide 1 on slide 2.
- Strongest proof goes right before the CTA, not buried mid-deck.
- Text: large, high-contrast, centered, clear of right-edge icons + bottom caption zone.
- Caption (200+ chars, 3–5 hashtags) reinforces hook, doesn't repeat it word-for-word.
- Rank by qualified conversations → customers, never views.

## 1. Problem → Workflow (core converter)
Structure: hook(problem) → problem proof → workflow step → workflow step → result → CTA.
- S1: "UK electricians — still doing quotes at 9pm?"
- S2: "62% of calls missed while on tools." (playbook pain)
- S3: "Customer WhatsApps at 2pm. AI drafts quote in 30 seconds."
- S4: "You approve on your phone between jobs."
- S5: "Customer gets a professional quote by 2:15pm."
- S6: "DM QUOTE for £499 setup. 14 days fixes."
Use for: cold awareness. Matches sales opening almost verbatim.

## 2. Before / After
Structure: hook(contrast) → before → after → before → after → close.
- S1: "Same electrician. Same business. Different tools."
- S2: "Before: missed 3 calls, quotes at 11pm."
- S3: "After: AI answered all 3, quotes by 4pm."
- S4: "Before: Sundays doing admin."
- S5: "After: invoicing + scheduling + follow-ups handled."
- S6: "£499 one-off. No subscription."
Use for: consideration. Instantly legible, high completion.

## 3. Diagnostic ("if your X looks like this…")
Structure: hook(symptom) → self-check → self-check → hidden problem → fix → CTA.
- S1: "If your inbox looks like this, you're losing jobs."
- S2: "3 unread enquiries from yesterday?"
- S3: "Quotes sent after 10pm?"
- S4: "That's not a workload problem. It's a triage problem."
- S5: "AI triages, drafts, reminds. You approve."
- S6: "DM DIAGNOSIS — I'll score your setup free."
Use for: warm viewers. Anyone matching the symptom is a qualified lead by slide 3.
From Slidetik diagnostic pattern; maps to discovery Qs 1–4 in playbook.

## 4. Teardown ("I ran ops on X — here's what broke")
Structure: hook(confession) → what was tried → break 1 → break 2 → what actually works → CTA.
- S1: "I ran a sparkie's admin on spreadsheets for a month."
- S2: "Day 3: lost a £800 job to a faster quote."
- S3: "Day 11: double-booked Tuesday."
- S4: "Day 20: £2k in unsent invoices."
- S5: "The fix isn't trying harder. It's triage + drafts + reminders."
- S6: "We install it in ~1 hour. DM TEARDOWN."
Use for: reach (reads as journalism, not ad). Keep numbers plausible, never invented.

## 5. Mistake / Loss ("we burned £X doing Y")
Structure: hook(loss + number) → common mistake → cost → the one change → proof → CTA.
Highest-converting B2B pattern per Slidetik (loss aversion + pre-qualification).
- S1: "Missing 2 calls a week costs ~£2k/month in lost jobs."
- S2: "Mistake: 'I'll call back tonight.'"
- S3: "By tonight they've booked someone else."
- S4: "Change: AI answers in 30 seconds, you call back with a quote."
- S5: "Setup £499. Pays for itself in week one."
- S6: "DM MATH — I'll estimate your missed-call cost."
Caveat: only use numbers you can defend (£499 payback claim is in playbook; keep "typically" framing).

## 6. Comparison ("cheap X vs real Y")
Structure: hook(choice) → option A → option B → decision criteria → verdict → CTA.
- S1: "Tradify vs AI Onboard — what actually changes?"
- S2: "Tradify: great job management. You still do the admin."
- S3: "AI Onboard: connects Tradify + email + calendar + WhatsApp."
- S4: "Criterion: who does the work — you, or the system?"
- S5: "We don't replace Tradify. We make it run itself."
- S6: "Already on Tradify? DM CONNECT."
Use for: objection handling ("I already use Tradify"). Never insult the alternative.

## 7. Objection → Proof
Structure: hook(question) → doubt → hard visual/proof → doubt → proof → CTA.
One objection per deck. Pull language from playbook table.
- "Too expensive?" → "£499 vs one lost £800 job." + founding £299.
- "Too busy?" → "1-hour setup, Friday afternoon, runs itself."
- "Don't trust AI?" → "You approve everything. AI drafts, you send."
- "Not tech-savvy?" → "If you use WhatsApp, you can use this."
Each needs a hard visual: price comparison, calendar block, approval screenshot.

## 8. Save-bait Checklist ("save this before…")
Structure: hook(utility) → item → item → item → item → save-CTA.
- S1: "5 things to check before you pay for any AI setup."
- S2–S5: one check each (approvals? your data stays yours? works with Tradify? real demo? fixed price?).
- S6: "Save this. DM CHECKLIST for the full version."
Use for: saves (strongest algorithm signal) + retargeting pool. Must be genuinely useful, not filler.

## What NOT to run
- Title-card openers ("AI Onboard presents…") — delays payoff, kills swipe 1.
- Product-first slide 1 — triggers ad reflex.
- 10+ slide decks — completion collapses past 8.
- Walls of text (>15 words/slide) — fast swipes can't read them.
- Multi-CTA closes ("follow + save + DM + visit site") — one action only.
- Generic trending-audio mismatch — pick restrained bed for education, stronger hit for reveals.
